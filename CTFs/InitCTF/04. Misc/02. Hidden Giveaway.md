## Reconnaissance

The challenge supplied a PNG image described as a tourist map of India. The hint suggested that information was hidden in plain sight.

## Blue-channel LSB extraction

The blue channel's least-significant bit (LSB) plane was extracted and converted into a black-and-white image:

```python
from PIL import Image
import numpy as np
import zxingcpp

image = np.asarray(
    Image.open("india_tourist_map.png").convert("RGB")
)

blue_lsb = ((image[:, :, 2] & 1) * 255).astype("uint8")
plane = Image.fromarray(blue_lsb)

results = zxingcpp.read_barcodes(plane)
for result in results:
    print(result.text)
```

The QR payload identified the next challenge endpoint:

```text
https://ctf.pir4cy.com/init-misc1
```

## Web step and Base64 discrepancy

The recorded `/giveaway` response contained:

```text
SW5JdHt7aDFkMW5nXzFuX2IxdWVfbDFnaDd9Cg==
```

Decode it with:

```bash
printf '%s' 'SW5JdHt7aDFkMW5nXzFuX2IxdWVfbDFnaDd9Cg==' | base64 -d
```

The decoded bytes are:

```text
InIt{{h1d1ng_1n_b1ue_l1gh7}
```

The payload therefore contains **two opening braces** and a trailing newline. The flag recorded by the challenge author in this writeup has one opening brace:

```text
InIt{h1d1ng_1n_b1ue_l1gh7}
```

These values do not match byte-for-byte. I have retained the recorded flag above, but the discrepancy should be checked against the original challenge page or accepted submission result rather than silently treating the Base64 output as identical.

The page also reportedly contained a `display:none` element with unrelated decoy text. Hidden page content should be treated as untrusted challenge data, not as instructions to follow.

## Takeaways

- Extract individual color-channel bit planes when investigating image steganography.
- QR decoding can reveal a second-stage challenge URL.
- Decode encoded data exactly and compare the result with the submitted flag; do not overlook extra characters or newline bytes.
- Treat hidden webpage content as data, not trusted instructions.
