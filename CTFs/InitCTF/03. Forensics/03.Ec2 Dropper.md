# EC2 Dropper

**Category:** Forensics  
**Points:** 200  
**Challenge ID:** 8

## Challenge brief

The challenge provided `/opt/agent/vault.py`, which decrypts a local vault. The encryption key is derived from an EC2 instance identifier. The objective is to recover the operator note.

## Investigation

1. The script showed that the key derivation was `SHA-256("s4lt_" + instance_id)`.
2. The vault format was `IV || AES-CBC(ciphertext)`.
3. The instance identifier was not embedded in the script.
4. The recorded investigation found the identifier in a cloud-init log:

   ```text
   i-0a1b2c3d4e5f67890
   ```

The key can then be derived from the known prefix and recovered instance identifier.

## Decryption

The original script removed padding by trusting the final plaintext byte. That is not sufficient validation: malformed or incorrectly decrypted data can cause arbitrary bytes to be removed.

This version validates PKCS#7 padding before decoding:

```python
import hashlib
from Crypto.Cipher import AES
from Crypto.Util.Padding import unpad

instance_id = "i-0a1b2c3d4e5f67890"

with open("vault.bin", "rb") as vault_file:
    blob = vault_file.read()

if len(blob) < 32:
    raise ValueError("Vault is too short to contain an IV and ciphertext")

iv, ciphertext = blob[:16], blob[16:]

if len(ciphertext) == 0 or len(ciphertext) % AES.block_size:
    raise ValueError("Ciphertext length is not a positive multiple of the AES block size")

key_material = ("s4lt_" + instance_id).encode("utf-8")
key = hashlib.sha256(key_material).digest()

padded_plaintext = AES.new(key, AES.MODE_CBC, iv).decrypt(ciphertext)
plaintext = unpad(padded_plaintext, AES.block_size, style="pkcs7")

print(plaintext.decode("utf-8"))
```

Recorded output:

```json
{
  "config_version": 2,
  "collected_region": "ap-south-1",
  "operator_note": "InIt{imds_k3y3d_s3cr3t_v4ult}"
}
```

## Security observations

- An instance identifier is metadata, not a secret key. If key derivation depends only on a predictable or discoverable identifier and a hard-coded prefix, it does not provide meaningful confidentiality.
- AES-CBC provides confidentiality only when used with sound key management and appropriate integrity protection. CBC alone does not authenticate ciphertext.
- Cloud-init logs and other bootstrap artifacts can contain sensitive configuration details; avoid logging secrets and restrict access to instance metadata and local logs.
- Prefer a managed secrets service or a properly designed key-management system over deriving encryption keys from public infrastructure identifiers.

## Reproducibility note

The instance identifier, vault format, and output above are the values recorded during this challenge run. The script assumes the file layout is exactly a 16-byte IV followed by AES-CBC ciphertext and that PKCS#7 padding was used.
