# Super Cookie

**Category:** Web · **Points:** 100 · **Challenge ID:** 24

---

**Brief.** An office story archive with an admin area; the cookie is "unsafe
somewhere."

**Path.**

1. `robots.txt` discloses the hidden admin path:

   ```
   Disallow: /admin/8f14e45f-ea9d-4b21-9c6d-62f8f7a6c311
   ```

2. Visiting it as a guest shows an admin login page that reflects the session
   identity (`You are currently browsing as: visitor`), confirming the page
   trusts the session cookie for role display.
3. The cookie is a Flask session cookie in `payload.timestamp.signature` form,
   e.g.:

   ```
   eyJyb2xlIjoiZ3Vlc3QiLCJ1c2VybmFtZSI6InZpc2l0b3IifQ.avhWcA.K_XIoCRq9uBhut4C3rGLyBY1iBY
   ```

   That is itsdangerous' `URLSafeTimedSerializer` with Flask's
   `key_derivation="hmac"` and `digest_method=sha1`.
4. Crack the signing secret offline against `rockyou.txt`. The correct
   derivation is:

   ```python
   k   = HMAC(secret, b"cookie-session")          # derived key
   sig = HMAC(k, payload + "." + timestamp)       # sha1
   ```

   Rockyou hits: **`secret123`**.
5. Forge an admin cookie. The page checks `role == "admin"` (not
   "administrator" — that variant only changes the displayed name):

   ```python
   {"role":"admin","username":"admin"}
   ```

   Full forged value used:

   ```
   eyJyb2xlIjoiYWRtaW4iLCJ1c2VybmFtZSI6ImFkbWluIn0.<ts>.<sig>
   ```

6. Send it to the admin path; the page returns the flag.

**Flag.** `InIt{C00k1e_F0rg3ry_1s_Sup3r}`

**Takeaway.** Signed cookies are only as strong as the signing key. A weak Flask
`SECRET_KEY` lets an attacker mint any role; the `robots.txt` disclosure just
told us where to use it.
